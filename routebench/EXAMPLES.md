# 三个必看推演案例（可在 UI 顶部一键加载，也可直接调 API）

所有案例的模拟器结论都在 `tests/test_frr.py::test_lab_simulator_matches_container`
中与真实 FRR 容器逐前缀对照（`pytest --run-frr`）。

---

## 案例 1 · 更具体路由误放行（v4-over-permit）

**意图**：放行 `10.0.0.0/8` 内 /9–/24 业务前缀，封锁测试段 `10.1.0.0/16` 及其全部明细。

**变化前（生效次序）**
```
0  deny  10.1.0.0/16 ge 16 le 32      # 封锁测试段及全部明细
1  permit 10.0.0.0/8  ge 9  le 24     # 放行业务掩码
```

**误操作**：在最前插入“明细放行洞”，并残留一条细化拒绝（r4，将被遮蔽面板指出）
```
0  permit 10.1.0.0/16 ge 24 le 32     # r3 误加
1  deny   10.1.0.0/16 ge 16 le 32     # r2 原规则：/16-/23 仍生效，/24+ 被遮蔽
2  permit 10.0.0.0/8  ge 9  le 24
3  deny   10.1.0.0/16 ge 17 le 23     # r4 永远不可达（单条遮蔽，r2 已全覆盖）
```

**语义面板给出的最小变化集合（不是文本行）**

| 见证前缀 | 变化前 | 变化后 | 含义 |
|---|---|---|---|
| `10.1.0.0/24` | deny(r2) | permit(r3) | **误放行**：测试段明细开始泄漏 |
| `10.1.0.0/25`（代表 ge24..le32 整个长度带） | deny(r2) | permit(r3) | 含 `/32` 主机路由 `10.1.0.1/32` |

遮蔽面板同时报告：`r4 被 r2 单条遮蔽`，并给见证 `10.1.0.0/17 → 命中 r2`。

**容器预期**：frr-b 的 BGP RIB 在变化后新增 `10.1.0.0/24`、`10.1.0.1/32` 等；
`10.1.0.0/16` 仍收不到。

## 案例 2 · 规则换序（v4-reorder）

**变化前**：例外拒绝在前（正确）
```
0  deny   10.1.0.0/16
1  permit 10.0.0.0/8 ge 9 le 24
```

**变化后**：有人按“先放行后例外”重排
```
0  permit 10.0.0.0/8 ge 9 le 24
1  deny   10.1.0.0/16
```

**最小变化集合**

| 见证前缀 | 变化前 | 变化后 |
|---|---|---|
| `10.1.0.0/16` | deny(r2) | **permit(r1)** |

遮蔽面板：变化后 `r2 被 r1 单条遮蔽`（/16 落在 ge9..le24 锥形内），该规则成为死规则。
`10.2.0.0/16` 等其他前缀两版都放行——最小集合不会用无关前缀刷屏。

## 案例 3 · 默认动作变化（v4-default-flip）

规则一行不动，`default_v4: deny → permit`。文本 diff 只有一个布尔值变化，
但语义面板按区域列出所有未显式命中空间的翻转，例如：

| 见证前缀 | 变化前 | 变化后 |
|---|---|---|
| `0.0.0.0/8`、`0.0.0.0/9` | 默认 deny | **默认 permit** |
| `10.0.0.0/8`（聚合自身，不被 ge9 命中） | 默认 deny | **默认 permit** |
| `10.0.0.0/25`（超出 le24） | 默认 deny | **默认 permit** |

`10.0.1.0/24` 等显式命中的前缀**不在**集合中——默认动作翻转不影响它们。
容器侧：A 的 prefix-list 尾部出现 `permit 0.0.0.0/0 le 32`，B 的 RIB 会收到
`192.0.2.0/24`、`8.8.8.8/32` 等此前被隐式拒绝的路由。

## 案例 4（IPv6，v6-over-permit）

同构地验证 v4/v6 不混算：误加 `permit 2001:db8:1::/48 ge 56 le 64` 后，
最小集合只有 `2001:db8:1::/56`（代表 /56–/64 长度带）；`2001:db8:1::/65`
超出 le64 仍被 deny，不会出现在翻转集合。另附一条 r4
（`deny ... ge 72`）演示 v6 单条遮蔽。IPv6 见证总数有界（< 120 个单元），
不随地址空间位数枚举。

## 回放与生效次序

每条持久化策略的编辑都写入 `journal`：

```
seq 0  reset        {policy: 基线全量}
seq 1  add_rule     {rule: deny 10.1.0.0/16}
seq 2  move_rule    {rule_id: r2, position: 0}
seq 3  set_default  {family: ipv6, action: permit}
```

`POST /api/policies/{id}/replay` 从 seq=0 顺序重放全部 op，逐步比对
`matches_recorded`，并检测重放末态与库内现状是否漂移；前端“回放”页逐步展示
每一步后的完整规则表。`seed.py` 创建的 `demo-reorder` 即一条
`reset → move_rule` 的可回放示例。
